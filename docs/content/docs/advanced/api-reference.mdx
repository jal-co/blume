---
title: OpenAPI / AsyncAPI
description: Drop in an OpenAPI spec and get real, searchable reference pages — one per operation — rendered natively by Blume.
---

Point Blume at an OpenAPI spec and it renders a **native API reference**: one real
Blume page per operation, with stable URLs, sidebar entries grouped by tag,
full-text search, `llms.txt` presence, and per-operation SEO. The hard part —
parsing, `$ref` resolution, circular references, and up-converting Swagger 2.0 /
OpenAPI 3.0 to 3.1 — is delegated to a maintained parser; Blume owns only the
finite render walk over the normalized schema.

```ts blume.config.ts lineNumbers
openapi: {
  enabled: true,
  spec: "https://petstore3.swagger.io/api/v3/openapi.json",
}
```

That mounts an overview at `/reference`, one page per operation under
`/reference/<tag>/<operationId>`, and a header link to the reference. The `spec`
is either an `http(s)` URL or a path to a local file in your project.

:::note
Unlike a self-contained embed, native operations are **first-class Blume
pages** — they show up in the content sidebar, the site search index, your
`llms.txt`, the sitemap, and get their own canonical URL and OG image, just like
any other page.
:::

## A local spec

A relative path is resolved from your project root and parsed at build time, so
the reference works offline. Both JSON and YAML specs work, and Swagger 2.0 /
OpenAPI 3.0 / 3.1 are all accepted (older dialects are up-converted to 3.1
internally):

```ts blume.config.ts lineNumbers
openapi: {
  enabled: true,
  spec: "./openapi.yaml",
}
```

## Route

`route` controls the base route — the overview page and the prefix every
operation page lives under (and the header link's target):

```ts blume.config.ts lineNumbers
openapi: {
  enabled: true,
  route: "/api",
  spec: "./openapi.yaml",
}
```

## Multiple specs

Use `sources` to publish more than one spec. Each source gets its own base route
and header link. Give each a `label` (used for the link and the sidebar group),
or set an explicit `route`:

```ts blume.config.ts lineNumbers
openapi: {
  enabled: true,
  sources: [
    { label: "Public API", spec: "./public.json" },
    { label: "Admin API", route: "/admin", spec: "./admin.json" },
  ],
}
```

`spec` is shorthand for a single-entry `sources`, so you only reach for `sources`
when you have more than one.

## Graceful degradation

The renderer covers the common 80% of schema shapes directly — objects, arrays,
enums, `oneOf`/`anyOf` unions, `allOf` (merged into a single object), and the
full set of validation constraints. Anything it can't model cleanly (exotic
conditional or `unevaluated*` JSON Schema) degrades to a collapsible raw-schema
box rather than breaking the build, and circular references stop at a labeled
link instead of expanding forever. **Nothing ever breaks; worst case it
degrades.**

## The Scalar renderer

For specs the native renderer can't yet do justice — or if you prefer Scalar's
design and its interactive request playground — set `renderer: "scalar"` to keep
the legacy self-contained [Scalar](https://scalar.com) embed on a single route:

```ts blume.config.ts lineNumbers
openapi: {
  enabled: true,
  renderer: "scalar",
  spec: "./openapi.yaml",
  theme: "purple", // a Scalar theme name (scalar renderer only)
}
```

The Scalar embed mounts inside Blume's shell but is self-contained: it brings its
own sidebar, search, and theme, and does **not** weave into Blume's content
sidebar, site search, or `llms.txt`. By default Blume layers your
[accent and radius](/docs/configuration/theming) onto Scalar's theme; `theme`
picks a specific Scalar theme instead.

## AsyncAPI

Event-driven APIs use a sibling `asyncapi` block with the **same shape**, always
rendered through Scalar (the native renderer is OpenAPI-only). Only the default
route differs (`/events`):

```ts blume.config.ts lineNumbers
asyncapi: {
  enabled: true,
  spec: "./asyncapi.yaml",
}
```

:::warning
Scalar's AsyncAPI support is still a work in progress — it renders channels,
operations, messages, and a Models section, but there's **no interactive
playground** for events yet. It improves upstream over time.
:::
